# 统计口径规范

> 生效日期：2026-10-08
> 起因：非标准列名计数历经 6 轮修订（4 → 24 → 684 → 761 → 722 → 711），
> 表级数字出现 9 个值（92 / 94 / 65 / 67 / 1141 / 1165 / 1168 / 1169 / 1171）。
> **根因不是算错，是跨口径相减与裸数字对比。**

---

## 一、强制规则

### 规则 1：任何统计量必须带口径标签

**禁止裸数字。** 出现数字时必须能回答「什么口径」。

| 标签 | 定义 | 用途 |
|---|---|---|
| `[严格]` | 剔除元数据表 + 剔除 UDF | 唯一有业务意义的口径，对外引用只准用这个 |
| `[含UDF]` | 剔除元数据表，UDF 计入 | 仅供与历史数据换算 |
| `[双来源并集]` | fields.json 并集 tables.json，剔除元数据表 | 解释「表清单与字段清单不一致」 |
| `[字段级]` / `[表级]` | 统计对象粒度 | 必须与口径标签组合使用 |

**正确写法**：

```
非标准列名 [严格][字段级] = 711
部分非标准表 [严格][表级] = 67
```

**错误写法**：

```
非标准列名 711 个        ← 无法判断口径
711 - 22 = 689          ← 跨口径减除，架构师 1141就是这么来的
```

### 规则 2：禁止跨口径相减

所有减法必须同口径。反例（本轮实际发生）：

```
含 UDF 表数 1168 − 全非标准表数 27 = 1141   ← 不同口径，结果无意义
```

### 规则 3：断言值必须带口径前缀

```python
assert cnt_ns_field_strict == 711, "[严格][字段级] 非标准列名"
assert cnt_tbl_partial_strict == 67, "[严格][表级] 部分非标准表"
```

### 规则 4：表级统计必须声明「表集合来源」

元数据有 `fields` 侧与 `tables` 侧两份表清单，**差 4 张**。
表级统计前必须声明用哪一侧或并集，否则同一指标会有两个值。

| 基准 | 数量 | 适用 |
|---|---|---|
| `并集`（默认） | 1171 | 推荐 —— 孤儿表有完整定义不应排除 |
| `tables`侧 | 1167 | 仅当明确知道孤儿表不应纳入 |
| `fields`侧 | 1170 | 罕见 |

### 规则 5：新发现的变体登记为独立类别，不改基础判据

## 二、字段级基准（`[严格]` 口径）

| 指标 | 数值 | 说明 |
|---|---|---|
| 业务字段总数 | 26798 | 全量 54842 − 元数据表 108 − UDF 27936 |
| 标准字段 | 26087 | 并集判据 |
| **非标准字段** | **711** | 对外唯一数字 |
| 真异常字段 | 22 | 含中文 20 + 纯数字 2 |
| 正常变体 | 689 | 7位式 338 + 表别名前缀式 257 + 纯字母 65 + 双侧皆不符 27 + 其他 2 |

### 命名判据（已冻结）

```
形态标准 := ^[A-Z]{2}\d{3}$
实体位:= { table[-2:], table[3:5] }    ← 并集，单侧会误判
```

**为何必须并集**（7 张表两种位置命中数不同，实测）：

| 表 | n | `t[-2:]` | `t[3:5]` |
|---|---|---|---|
| `ACTMS205` | 8 | **0** | **8** |
| `ACTTI205` | 12 | **0** | **12** |
| `DSCINTMA` | 5 | **5** | **0** |
| `WARRANT` | 6 | **6** | **0** |

## 三、表级基准

### 3.1 先固定「表集合来源」（多次分歧的根源）

元数据存在**两份表清单**，口径不同结果不同：

| 表集合 | 数量 | 差异 |
|---|---|---|
| `fields` 侧 | 1170 | 有字段定义 |
| `tables` 侧 | 1167 | 有中文名与模块（已剔元数据表与 PMSTA） |
| **并集** | **1171** | 剔除元数据表后的完整集合 |

差集构成：

- 仅在 `fields`（孤儿表，有完整字段定义）：`INVLK` `INVLL` `YFMXB` `YSMXB`
- 仅在 `tables`（无任何字段）：`PMSTA`

**裁决：以并集 1171 为表级统计基准。**

理由：`YFMXB` / `YSMXB` 有完整字段定义（如「币种」「出入」「付款金额」），
排除它们等于让有效数据凭空消失；`PMSTA` 表名单独存在应显式标注而非隐去。

### 3.2 `[严格]` 口径（剔除 UDF）—— 唯一有业务意义

| 指标 | 数值 |
|---|---|
| 业务表总数 | **1171** |
| 全部字段均标准 | 1080 |
| **全字段非标准表** | **27** |
| **部分非标准表** | **67** |
| **含 >=1 非标准字段表** | **94** |
| 含 UDF 表数 | 1169 |

勾稽：`27 + 67 = 94`（成立）　`1080 + 91 = 1171`（成立）

### 3.3 关键区分（QA 曾据此指出我的错误）

**「含 UDF 表数 1169」与「含 >=1 非标准字段表 1168」是两个独立的量，不构成修正关系。**

```
含 UDF 表数                1169   <- 表级 UDF 覆盖
含 >=1 非标准字段表（含UDF） 1168   <- 1169 减去无 UDF 且无异常字段的表
两者相差 1 张，不存在包含关系，禁止相减
```

我此前把 1165 当成 1168 的「未剔元数据表版」，属于**误读**。

### 3.4 关于 65 / 92 与 67 / 94 的差异（QA 定位）

**根因是表集合基准不同，不是算错，无需「对齐」，只需标注基准。**

```
表集合 = tables 侧 1167  ->  部分非标准 65 / 含 >=1 非标准 92
表集合 = 并集1171      ->  部分非标准 67 / 含 >=1 非标准 94
差异 2 张 = 仅在 fields 侧的孤儿表
```

## 四、掩码异常基准

### 众数基准法

按 (type_raw, mask) 分组，取组内 precision **众数**为基准；
仅当 type_raw 为 char 且偏离众数时计为异常。

**为何不能用绝对值比对**：MD006(precision) 在不同 MD005 下语义不同 ——

| MD005 | 语义 | 分布 |
|---|---|---|
| char | **字符长度** | 1.0 / 4.0 / 8.0 / 10.0 等 |
| date | 恒为 .0（原生 date 不存长度） | 22/22 全是 .0 |
| numeric | 数值 scale | 16.6 占 84.79% |

用 char 的标尺去量 date，会产生 9 条假异常。

### 众数占比（全部 ≥98%，故众数作基准安全）

| 掩码 | 组内数 | 众数 | 占比 |
|---|---|---|---|
| YMD | 830 | 8.0 | **99.4%** |
| YM | 82 | 6.0 | **98.8%** |
| YMK | 29 | 8.0 | 100% |
| Y | 22 | 4.0 | 100% |
| HHMMSSMMM | 4 | 9.0 | 100% |
| YYYY/MM/DD | 2 | 10.0 | 100% |
| YYMMDDHHMM | 1 | 10.0 | 100% |

**建议断言**：`min(mode_ratio) >= 0.98`。若某掩码众数占比跌破 98%，
说明该掩码语义混用，需人工介入而非自动判异常。

### char 6 条异常（方向是事实，成因是推断）

| 方向 | 数量 | 明细 | 判定（事实） | 成因（推断） |
|---|---|---|---|---|
| **偏小** | 4 | `HRSTC.TC015/TC016`(6 vs 8)<br>`PALNF.NF014/NF015`(6 vs 8) | precision < 众数 | 疑挂错掩码（YMD 8 位装不进 6 位列） |
| **偏大** | 2 | `CMSMA.MA169`(10 vs 6)<br>`ASMTS.TS008`(12 vs 8) | precision > 众数 | 列宽预留过大，掩码未必错 |

> `CMSMA.MA169` 挂 YM **本身是对的**（中文名「固定资产现行年月」正是年月），只是列宽 10 > 6。
> 归入「挂错掩码」会误导开发者去改本正确的掩码。
