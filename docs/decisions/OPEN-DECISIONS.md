### OPEN-A3 ｜`conditions` 方言差异的处置

| 项 | 内容 |
|---|---|
| **原问题** | 易飞 `conditions` 为对象嵌套 `group`、易助为数组嵌套 `groups`，是否需要抽象兼容层？ |
| **状态** | ✅ **RESOLVED**（2026-10-08，用户裁定） |
| **结论** | **不做兼容层，按产品线彻底分包。** `yfcli-sdk` 与 `yzcli-sdk` 各自独立实现，OpenAPI 层不通用。 |
| **理由** | ① 结构差异是**语义级**的（易飞支持 `group` 任意层级递归嵌套，易助不支持），强行兼容会引入两套语义；② 差异不匹配时**服务端静默返回全量、不报错**，兼容层的存在会让这类故障更难排查；③ 既然已确定完全物理隔离架构（独立仓 + 独立 MCP 进程），兼容层收益为零。 |
| **风险与对策（2026-10-08 真机实测后修正）**：
~~静默失败是最高风险项~~ → **实测证明易飞对错误 conditions 结构是显式报错**
（`code=-1` + `conditions not found.`），**风险等级由「最高」下调为「🟠 中」**。

结论不变但实现标准放宽：仍需 ConditionsTranslator，但只需提供**易飞结构的构造器** +
对数组形态**显式拒绝并给出清晰报错**，无需按「防静默失效」的双向兼容标准实现。

真机证据见 `docs/plans/yf-live-probe-report.md` §三。
