## 四、根因判断

三条主因，决定了差异的性质：

1. **同一协议族，不同实现**（`digi-*` 头 + `std_data` 封包 + `execution.code` + `result.success/error` 完全同构）→ 所以**大部分规则可直接复用**，改造量可控
2. **易飞侧文档质量低于易助侧**：`error[]` 双结构、繁简混用、`docdate`/`doc_date` 并存、`udf07~12` 编号跳号、URL 4 种变体——这些是**易飞侧的规范疏漏**，移植时必须做防御性编码
3. **易助侧有工程化加固，易飞侧没有**：TypeKeyList 服务 / help 服务 / fastquery SQL 缓存 / `TPASC19` Token 获取说明 / 16,632 行字段对照表——这些**不是协议要求，是易助项目自己建的基建**，易飞侧需**从零补建**
