## 2. 公共请求头与鉴权

### 2.1 四个必填 Header（通则·报头）

| 参数名               | 参数值                               | 是否必须 | 描述                                   |
| ----------------- | --------------------------------- | ---- | ------------------------------------ |
| `digi-datakey`    | `{"CompanyId":"公司别编号"}`           | ✔    | **多公司的公司别编号**                        |
| `digi-service`    | `{"name":"接口名"}`                  | ✔    | 接口名，例：`yf.oapi.plant.data.query.get` |
| `digi-user-token` | 用户令牌                              | ✔    | 调用接口时根据此令牌进行身份认证校验权限                 |
| `Content-Type`    | `application/json; charset=utf-8` | ✔    | 固定值                                  |

**官方示例**（通则原文）：

```
digi-datakey:{"CompanyId":"{账套编号}"}
digi-service:{"name":"yf.oapi.plant.data.read.get"}
digi-user-token:{用户令牌}
Content-Type:application/json; charset=utf-8
```

### 2.2 鉴权机制

- **令牌制**：`digi-user-token` 为 48 位十六进制字符串
- **权限绑定**：身份令牌与易飞用户权限绑定，可在易飞 ERP 中管理身份信息及用户权限
- **权限维度**：OpenAPI 只能访问该用户拥有权限的功能，限定可访问的接口/数据/资源；**支持基本权限、成本权限、售价权限**（概述·四）
- **多公司隔离**：`digi-datakey` 的 `CompanyId` 决定操作哪个公司别（账套）
- **认证类型**：Apipost 全局 `auth.type = "noauth"`，接口级 `auth.type = "inherit"` → **鉴权完全由 Header 承载，无 OAuth/Bearer/API Key**

## 3. 请求体规范

### 3.1 固定封包（通则·http-body）

| 标签          | 是否必要 | 描述          |
| ----------- | ---- | ----------- |

```json

    "parameter": {
      "plant_data": [{
        "plant_no": "test01",
        "plant_name": "自定义字段示例",
        "udf01": "udf01value",
        "udf51": 51
      }]
    }
  }
}
```

### 3.2 查询（query）专用参数

| 参数                             | 说明                      | 约束                                                                                                      |
| ------------------------------ | ----------------------- | ------------------------------------------------------------------------------------------------------- |
| `page_no`                      | 页码                      | **从 1 开始**                                                                                              |
| `page_size`                    | 页面尺寸（每页数据量）             | **最大 10000**                                                                                            |
| `use_has_next`                 | 是否分页                    | 布尔                                                                                                      |
| `conditions`                   | 条件集合                    | 除「取全部资料」外皆必传                                                                                            |
| `conditions.operator`          | 条件组之间逻辑符                | `and`（默认，可缺省）/ `or`                                                                                     |
| `conditions.fields`            | 条件数组                    | 可为单一条件式或多字段复合                                                                                           |
| `conditions.fields.group`      | 条件组                     | 嵌套用，**可多层递归嵌套**                                                                                         |
| `conditions.fields.field_name` | 条件字段名称                  | 可用 `+` 拼接字段；**非主数据表字段必须加 `node_name`**                                                                  |
| `conditions.fields.value`      | 条件值                     | 字符串双引号包裹；数值不带引号                                                                                         |
| `conditions.fields.node_name`  | 数据表节点名                  | **查询单身字段时必填**（如 `sales_order_detail_data`）                                                              |
| `conditions.fields.operator`   | 逻辑操作符                   | `>` `>=` `=` `<` `<=` `like` `IN` `NOT IN` `BETWEEN` `EXISTS` `NOT EXISTS`；文档另提及 `<>` `LIKE` `NOT LIKE` |
| `orders`                       | 排序数组                    |                                                                                                         |
| `orders.field_name`            | 排序字段                    |                                                                                                         |
| `orders.order_type`            | 排序类型                    | `asc` / `desc`                                                                                          |
| `selectedColumns`              | 指定回传字段（**20260401 新增**） | 逗号分隔节点名                                                                                                 |

**分组层级规则**（查询服务·范例 6 原文）：

- 外层 `operator` 作用于**条件组之间**
- `group` 内 `operator` 作用于**组内条件式之间**
- `group` 可**嵌套 `group`**（范例 6 演示三层嵌套）
- 条件式与条件组可混合同级（范例 5）

**取值需带 SQL 片段的运算符**（易飞特有高危点）：

| 运算符                     | value 格式                                                       | 原文示例                                                                                    |
| ----------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `BETWEEN`               | `'<起>' AND '<止>'`                                              | `"value": "'00941229002' AND '00950320001'"`                                            |
| `IN` / `NOT IN`         | `('N'000',N'001')`                                             | `"value": "(N'000',N'001',N'002')"`                                                     |
| `IN` + 子查询              | `(SELECT ... FROM $$INVMB WHERE ...)`，**必须为数据表起别名**            | `"value":"(SELECT MB001 FROM $$INVMB WHERE INVMB.MB031<>'')"`                           |
| `EXISTS` / `NOT EXISTS` | `(SELECT ... )`，`field_name` **留空**                            | `{"field_name":"","operator":"EXISTS","value":"(SELECT MB001 FROM $$INVMB WHERE ...)"}` |
| `LIKE`                  | 通配符写在 value 内                                                  | `"value": "00%"` / `"%00%"`                                                             |
| `+` 拼接字段                | `field_name: "doc_type_no+doc_no"`、`"CREATE_DATE+CREATE_TIME"` | —                                                                                       |

**取全部资料**：`"conditions": {}`（空对象）。

**执行机制约束**（查询服务原文）：「**每次查询会重查数据库**，进行分页后返回指定页数据。」

## 5. 响应结构

### 5.1 固定层级（通则·Response）

```json
{
  "std_data": {                      // 固定根标签
    "execution": {                    // 服务调用状态
      "code": "0",                    // 0=成功；-1=失败
      "sql_code": "",                 // 系统预留字段
      "description": "查詢成功"        // code=-1 时为具体异常信息
    },
    "parameter": {                    // API 返回内容
      "result": {
        "success": [ ... ],           // 成功数据
        "error":   [ ... ]            // 失败数据
      }
    }
  }
}
```

| 标签            | 描述                          |
| ------------- | --------------------------- |
| `std_data`    | 固定标签，返回数据的根标签               |
| `execution`   | 固定标签，服务调用状态                 |
| `code`        | `0`=成功；`-1`=失败（异常，如找不到对应服务） |
| `description` | 状态码为 `-1` 时表示具体异常信息         |
| `sql_code`    | 系统预留字段                      |
| `parameter`   | API 服务返回内容                  |
| `result`      | 含 `success` 和 `error` 标签    |

**实测 code 分布**：`"0"` 出现 5157 次，`"-1"` 出现 1022 次。**仅两种取值**。

### 5.2 失败响应结构

```json
{
  "std_data": {
    "execution": { "code": "-1", "sql_code": "", "description": "查詢失敗" },
    "parameter": {
      "result": {
        "success": [],
        "error": [{
          "message": "该用户TEST没有权限",
          "data": {}
        }]
      }
    }
  }
}
```

**`error[].data` 会回显传入的出错数据**（实测 create 主键冲突示例）：

```json
"error": [{
  "data": { "customer_basic_data_file_data": { "customer_no": "00WKTEST", ... } },
  "information": [{
    "message": "ExecSQL Error Exception :违反了 PRIMARY KEY 约束“PK_COPMA”。不能在对象“dbo.COPMA”中插入重复键。重复键值为 (00WKTEST)。",
    "data": {}
  }]
}]
```

> ⚠️ **`error[]` 内部存在两种子结构**：一种用 `message`/`data`，一种用 `information[].message`/`information[].data`。这是**易飞侧实测存在的不一致**（见比对报告差异项）。

### 5.3 查询接口的返回层级（**与创建类不同**）

```json
{
  "std_data": {
    "execution": { "code": "0", "sql_code": "", "description": "查詢成功" },
    "parameter": {
      "total_result": 2,          // 满足条件的总笔数
      "has_next": false,          // 是否有下一页
      "result": {
        "cnt": 2,                 // 本页笔数
        "rows": [ { ... } ]       // 数据数组
      }
    }
  }
}
```

**读/删/审核类返回走** `parameter.result.success[]`（数组），**查询类走** `parameter.result.rows[]` + `total_result` / `has_next` / `cnt` —— **两条不同的数据通道**。

## 7. 版本管理与兼容策略

### 7.2 变更记录（更新说明文档，日期为版本锚点）

| 日期           | 变更内容                                 | 兼容性影响                     |
| ------------ | ------------------------------------ | ------------------------- |
| **20260401** | 查询类支持入参中执行回参，新增 `selectedColumns` 节点 | **向后兼容**（新增可选入参，老调用方不受影响） |
| **20260911** | **新增类 API 入参主表节点同时兼容数组和非数组**         | **向后兼容**（原本只接受数组，现在对象也接受） |

**20260911 兼容示例**：

```json
// 非数组（新增支持）
{ "std_data": { "parameter": { "supplier_basic_data": { "supplier_no": "PDPTEST01", ... } } } }

// 数组（原有用法）
{ "std_data": { "parameter": { "supplier_basic_data": [ { "supplier_no": "PDPTEST01", ... } ] } } }
```

### 7.3 版本管理策略

- Apipost 接口节点自带 `version` 字段（`1` × 2116，少数为 321/323/325/326 —— **疑为 Apipost 内部修订号，非业务版本**）
- **无正式版本号体系、无弃用政策、无向后兼容承诺文档**（文档未说明）
- 变更以「日期 + 变更点列表」形式记录，属**追加式变更日志**

## 8. 错误处理约定

### 8.1 双层错误模型

| 层   | 载体                               | 取值                       |
| --- | -------------------------------- | ------------------------ |
| 传输层 | HTTP 状态码                         | 文档仅登记 200 / 404（未说明完整语义） |
| 业务层 | `std_data.execution.code`        | `0` 成功 / `-1` 失败         |
| 业务层 | `std_data.execution.description` | 失败时的具体异常信息（中文）           |
| 数据层 | `parameter.result.error[]`       | 批量调用中失败项的明细              |

### 8.2 错误消息实测样本

| 场景    | `code` | `description` / `message`                                                                        |
| ----- | ------ | ------------------------------------------------------------------------------------------------ |
| 服务找不到 | `-1`   | 「服务调用，出现异常导致失败，例如找不到对应服务」                                                                        |
| 权限不足  | `-1`   | 「该用户TEST没有权限」                                                                                    |
| 主键重复  | `-1`   | 「ExecSQL Error Exception :违反了 PRIMARY KEY 约束“PK_COPMA”。不能在对象“dbo.COPMA”中插入重复键。重复键值为 (00WKTEST)。」 |
| 查詢成功  | `0`    | 「查詢成功」（**繁体字**）                                                                                  |
| 执行成功  | `0`    | 「执行成功」                                                                                           |
| 执行失败  | `-1`   | 「执行失败」                                                                                           |

> ⚠️ 成功/失败 description **繁体/简体混用**（`查詢成功` 繁体、`执行成功` 简体），属**文案不一致**。
