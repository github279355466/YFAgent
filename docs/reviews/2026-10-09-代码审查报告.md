## 1. P0 · 必须立即修复（安全 / 静默错误）

### P0-1 `[实测]` `yfcli-analysis/src/runtime/sql/template.ts:60` 视图白名单可被方括号标识符完全绕过

`extractTableRefs` 的正则为：

```js
const re = /\b(?:FROM|JOIN)\s+(?:dbo\.)?([A-Za-z_][A-Za-z0-9_]*)/gi;
```

方括号包裹的标识符 `[COPMA]` 完全匹配不到 → `tableRefs` 为空 → 白名单循环不执行 → **任意物理表、任意语句都能通过校验**。

实测：`SELECT TOP (:max_rows) a FROM [COPMA]` **通过校验**（应为拒绝）。
`[dbo].[COPMA]` 多段方括号名同样通过。

**影响**：L1 白名单门禁（自述的核心防线）在此形态下完全失效，可直查 ERP 物理表。
**修复方向**：显式支持并校验方括号/双引号标识符；禁止多段名；白名单改为词法解析而非正则截取。
**对应测试**：`[P0-1]`（2 项，均红）

### P0-2 `[实测]` `template.ts:82-90` 禁用词正则无右边界，误伤合法列名

```js
const re = new RegExp(`\\b${kw.replace("_", "[_]?")}`, "i");
```

缺右边界，导致子串命中：

| 列名 | 被误判为 | 实测结果 |
|---|---|---|
| `updated_at` | `update` | 被拒 |
| `create_date` | `create` | 被拒 |
| `exec_summary` | `exec` | 被拒 |

`create_date` 是易飞**管理字段**（AGENTS.md 明列 7 个管理字段之一），属真实可用列名。
**影响**：功能性缺陷——未来任何含这些前缀的列名都无法进入模板；当前 20 个模板侥幸未撞上。
**修复方向**：补右边界 `\b${kw}\b`；下划线按字面量转义。
**对应测试**：`[P0-2]`（3 项，均红）

### P0-3 `[实测]` `template.ts:104-118` CTE 被永久禁用，且与文件注释自相矛盾

`template.ts` 注释声称：

> 允许的上下文：FROM vw_ai_xxx / JOIN vw_ai_xxx / WITH ... AS (SELECT ... FROM vw_ai_xxx)

实测 `WITH cte AS (SELECT a FROM vw_ai_probe) SELECT TOP (:max_rows) a FROM cte` **被拒**，报「引用了非 vw_ai_* 视图/表『cte』」。

**影响**：文档承诺的能力不可用（功能与注释不一致）。
**修复方向**：把 CTE 名加入符号表，白名单改为「CTE 名 ∪ `vw_ai_*`」。
**对应测试**：`[P0-3]`（1 项，红）

### P0-4 `[实测]` `yfcli-analysis/src/runtime/sql/driver.ts:50-52` 占位符转换篡改字符串字面量

```js
export function convertPlaceholders(sql: string): string {
  return sql.replace(/:([A-Za-z_][A-Za-z0-9_]*)/g, "@$1");
}
```

不区分「字符串字面量内」与「真占位符」。实测：

```
输入: SELECT a FROM vw_ai_x WHERE s = ':end_date' AND t = :end_date
输出: SELECT a FROM vw_ai_x WHERE s = '@end_date' AND t = @end_date
                                        ^^^^^^^^^^^ 字面量被篡改
```

同类：`'see :foo doc'` → `'see @foo doc'`。

**影响**：这是**唯一改写 SQL 文本**的函数，且**无任何测试**。任何含 `:word` 形态的字符串字面量都会被静默破坏（业务语义错误，不报错）。
**修复方向**：先剥离字符串字面量与注释再替换；或改用 `sp_executesql` 风格的显式参数化。
**对应测试**：`[P0-4]`（2 项，均红）

### P0-5 `[实测]` `driver.ts:137-145` 存在绕过凭据红线的第二通道

- `config.ts:96-103` 用 `FORBIDDEN_KEYS` 拒绝 datasource 上的明文 `password`，其价值**完全在于**「连接串只能由 `user_env`/`password_env` 拼出」。
- 但 `createMssqlDriverFromEnv()` 提供**未被红线约束的第二条通道**：

```js
const connStr = process.env["YFCLI_DB_CONNECTION_STRING"];
// 形如 Server=x;User Id=sa;Password=明文
```

`validateSqlConfig` 一次都不会跑。且全仓 grep 确认：`resolveCredentials`（唯一合规路径）**除测试外无调用方**。

**影响**：红线「写的比读的严」——两条通道都在导出面，谁被接进生产无法保证。审计条目里 `dataSourceId` 亦为 `undefined`，事后无法追责。
**修复方向**：二选一并删掉另一条；若保留 env 通道，必须让其接受 `SqlDataSourceConfig` 并复用 `resolveCredentials`，禁止裸连接串入口；裁决记入 `docs/decisions/OPEN-DECISIONS.md`。
**对应测试**：`[P0-5]`（1 项，红）

### P0-6 `[实测]` `template.ts:176-181` `renderSql` 不校验调用方传入的 `maxRows`

```js
const maxRows = Math.min(requestedMaxRows ?? t.max_rows, t.max_rows);
```

实测 `renderSql(t, {}, 0)` → `values.max_rows = 0`；`renderSql(t, {}, -5)` → `-5`，原样透传。

**影响**：`TOP(0)` 返回空集，会被上层误判为「**无数据**」（与 AGENTS.md §真机实测硬约束 #2「主键全错返回 code=0 + 空数组」同型陷阱）。
**修复方向**：`requestedMaxRows` 必须为 ≥1 的有限整数，否则抛错。
**对应测试**：`[P0-6]`（2 项，均红）

### P0-7 `yfcli-auth/src/health-check.ts:73-75` 健康检查以 HTTP 200 为唯一判据，业务失败被误报为连通

```js
if (response.ok) {
  return { ok: true, latencyMs, error: undefined };
}
```

不解析 body 的 `execution.code`。与本仓既定契约「以 `code === "0" || "-0"` 判成功、**禁止字符串匹配 description**」相悖。

**影响**：token 错误等业务失败若以 HTTP 200 返回，健康检查报「连通」，掩盖真实故障。
**修复方向**：解析 `execution.code`，非成功码返回 `ok:false` 并携带 description。
**对应测试**：`[P0-7]`（2 项红；另 1 项 `code=0` 正常场景为护栏，绿）

### P0-8 `yfcli-auth/src/auth-factory.ts:47` 无 token 时以空串发请求

```js
const token = resolveCredentialFromEnv(config.tokenEnvVar, env) ?? '';
```

**影响**：向 ERP 发一个必然失败的请求（空 `digi-user-token`），浪费往返且污染健康检查语义。
**修复方向**：空 token 时短路返回明确错误，不发起网络请求。
**对应测试**：`[P0-8]`（1 项，红）

## 6. 值得肯定的设计

- `yfcli-sdk` 协议层分离干净：`assertHttpOk` **先判状态码**、双结构 `error[]` 兼容且**未识别结构显式抛错**（「错误被静默吞掉」的正确防线）、`redact.ts` 阻断 `error[].data` 回显、`enum-guard` 拦截「编码.中文」静默错误 —— 精准命中 AGENTS.md 记录的真机坑。
- `yfcli-analysis` 模板注册制 + `renderSql` 产出 `{sql,values}` 交驱动绑定、**绝不内联参数**，从根上消掉「参数值注入」这一类风险；执行器 `min(调用方,模板,数据源)` 三重取小 + 结果二次截断。
- `erp-license/src/crypto/aes-key.ts` 明确拒绝硬编码回退；`hmac.ts` 用 `timingSafeEqual`。
- `template.ts` 对空 `IN`/`BETWEEN`/空串的**显式拒绝**，把易飞的静默错误提前到本地。
- CI（`.github/workflows/verify.yml`）的 `scan-secrets` + 冻结口径门禁设计合理，且注释解释了「门禁 3 为何不可删」。

## 7. 结论

三个项目的**分层架构是对的**，但存在共同的系统性模式：**「声明的安全/正确性契约」强于「实际接线」**。`yfcli-analysis` 的 L1/L3 防护强度远低于自述（§1 已实测绕过），`yfcli-auth` 的 `limits`/凭据扫描无落地，`erp-experts` 多处「简化占位」未在接口上标记。

当前尚未接真机、各包既有测试全绿，**正是修 P0/P1 的窗口期**。
