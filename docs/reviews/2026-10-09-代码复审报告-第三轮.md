`TS2305` 编译失败。本轮删除该导出项，`yfcli-analysis` 全包恢复可编译：

```
packages/yfcli-analysis > npx tsc --noEmit   →  exit 0
```

**为何第一轮 60 项测试全绿却没发现**：第一轮 P0-5 用例直接 `import("../src/runtime/sql/driver.js")`，
绕过了 `index.ts` 这一真实消费入口。第二轮新增的 `p0b-regression.test.ts` 刻意从入口断言，
本轮已将其从红转绿。

### P0-B 表白名单改为词法扫描（fail-closed）

**根因**：`extractTableRefs` 用正则截取「紧跟 FROM/JOIN 之后的一个标识符」，
而 T-SQL 的标识符引用与连接语法是开放集合——漏掉任意一种写法即等于门禁失效。

**新实现**（`template.ts`）：

1. `tokenizeSql()`：把 SQL 拆成 token 流，处理单引号字符串（含 `''` 转义）、
   `--` 行注释、块注释、`[]` 方括号标识符（含 `]]` 转义）、`""` 双引号标识符、裸标识符、标点。
2. `extractTableRefs()`：在 token 流上定位 `FROM` / `JOIN` / `INTO` / `APPLY` 引出位置，
   取其后标识符链的**最后一段**（`dbo.vw_ai_x` → `vw_ai_x`），并继续吃同一子句内的逗号连接表名。
3. 无法识别的表位（如 `FROM` 后直接跟 `SELECT`）记录为空串，在门禁处按「非法」拒绝。

**实测矩阵（27 例，全对）**：

| 类别 | 用例 | 结果 |
|---|---|---|
| 应拒绝 | `[COPMA]`、`[dbo].[COPMA]`、`[[COPMA]]`、`"COPMA"` | 全 reject |
| 应拒绝 | `vw_ai_x, [COPMA]`、`vw_ai_x, dbo.COPMA`、`vw_ai_x, vw_ai_y, COPMA` | 全 reject |
| 应拒绝 | 子查询内 `dbo.COPMA`、`JOIN COPMA`、`LEFT JOIN [COPMA]`、`EXISTS(... , [COPMA] ...)` | 全 reject |
| 应拒绝 | `FROM /* x */ [COPMA]`、换行后 `[COPMA]`、`INTO COPMA` | 全 reject |
| 应通过 | `vw_ai_x`、`dbo.vw_ai_x`、`[vw_ai_x]`、`[dbo].[vw_ai_x]` | 全 accept |
| 应通过 | `JOIN vw_ai_y`、`vw_ai_x, vw_ai_y`、CTE（单/多）、子查询合法视图 | 全 accept |
| 应通过 | 字面量 `'from COPMA'`、行注释内 `-- from COPMA`、函数参数、列清单逗号 | 全 accept |

### P0-C 凭据通道收敛为唯一路径

**改动**（`driver.ts`）：

- `MssqlDriverOptions` 由 `{connectionString?, server?, port?, database?, user?, password?, options?}`
  改为 `{dataSource: SqlDataSourceConfig, resolveCredentialsFn?}`。
  **类型层面不再提供任何明文入口**，并保留原设计意图的注释说明「为何刻意不提供」。
- `getPool()` 改为调用 `resolveCredentials(dataSource)`（唯一合规路径）取凭据；
  变量命名从 `user`/`password` 改为 `creds.user`/`creds.password`，不再有裸字段。
- 构造函数增加**运行时兜底**：若仍传入 `connectionString`/`password`/`pwd`/`user`/`uid`，
  立即抛 `AnalysisError`；缺 `dataSource` 同样抛错。
  这样「传了明文却没用上」不会被误认为凭据已配置。
- 文件头注释中的 `YFCLI_DB_CONNECTION_STRING` 与 `Password=xxx` 示例已移除。

### P1-B `compute` 返回类型固定，分组走显式 API

**问题**：为兑现 `scope.groupBy: ["item_no"]`，`compute` 被改成「有时返回结果、有时返回结果字典」，
并用 `return result as never` 关闭类型检查——调用方无法静态判断拿到什么。

**改法**：

- `types.ts`：`FormulaDefinition` 新增可选 `computeGrouped?: (rows) => Record<string, FormulaResult>`，
  并在 `compute` 上补充注释说明「返回类型固定，需分组请用 computeGrouped」。
- `formulas.ts`：`compute` 恢复为**恒定返回单个 `FormulaResult`**（全部行并成一个总额）；
  分组逻辑移入新的 `computeGrouped`，且：
  - `scope.groupBy` 为空 → 抛 `ExpertError`
  - 输入为空 → 抛 `ExpertError`
  - **groupBy 字段在部分行缺失 → 抛 `ExpertError`**（契约漂移必须暴露，不静默并成一组）
- 全仓已无 `as never`。

对应的 4 项测试已重写（原先用 `result as unknown as Record<...>` 断言旧行为）：

| 用例 | 实测 |
|---|---|
| `computeGrouped` 按 item_no 分组 | 通过 |
| `compute` 返回类型不随输入变化（值为 6000） | 通过 |
| `computeGrouped` 字段缺失必须报错 | 通过 |
| `computeGrouped` 空集必须报错 | 通过 |
