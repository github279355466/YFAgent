## 一之二、架构裁决（2026-10-09）

**结论：YFAgent 应与 YZCLI 保持同一双通道架构。**

| 通道 | 走法 | YZCLI 现状 | YFAgent 现状 |
|---|---|---|---|
| CRUD 增删改查 | ERP OpenAPI | `yzcli-sdk/client.ts` | ✅ 单包 9 个源码子目录已建，未接真机 |
| 分析聚合 | 数据库直连 + 只读视图 | `yzcli-analysis` + 9 个 `vw_ai_*` | ❌ **缺失（D-13）** |

**视图方案**：易飞库无 `vw_ai_*` 分析视图（实测仅 4 个：`MoJu` / `VCMSMQZ` / `VCOPTH` / `VMOCTE`）。照易助视图定义改写为易飞表名，**由客户侧 DBA 手动执行建库脚本**（D-14）。

**视图设计裁决**：视图**不带 `COMPANY` 过滤** —— `COMPANY` 为预留管理字段（无业务含义），易飞架构为「独立公司账套」，不存在一表多账套。

**库表名一致性（已验证）**：3 位前缀交叉比对 52 组，**52 组一致 / 0 组不同**。字典表名与库表名同名，**无需映射层**。

**其余基线阻塞**：`--verify-stats` 未反向读真实产物，存在「改产物不改自报数」的绕过路径（已降级为 D-01/P2）。

## 六、给 codex 的交接说明

1. **先读这两份**，它们是所有决策的源头：
   - `docs/decisions/OPEN-DECISIONS.md` —— 22 条裁决，含 8 条真机实证

2. **易飞 API 的 9 条硬约束**在 `AGENTS.md`，动手前必读，尤其：
   - 枚举查询只传编码（混用静默返回空集）
   - 主键全错返 `code=0` + 空数组（不报错）
   - 错误 token 返 HTTP 500 + HTML（不是 JSON）
   - 字段名无语义（`TC001` 非 `doc_type_no`），必须查字典

3. **文件所有权**（2026-10-08 定）：
   - `scripts/gen_data_dictionary.py` —— 单一 owner，其他角色只提 issue
   - `scripts/*.mjs`、`packages/yfcli-sdk/src/**` —— 开发侧可改
   - 校验脚本（`qa_*.py` / `_verify_*.py`）—— QA 与架构师，只读

4. **提交前必跑**：`npm run verify`（敏感扫描 + 四类产物校验）。

5. **工程纪律**（`AGENTS.md` 有详版，踩坑 5 次的教训）：
   - 含反引号的中文文本 → 落文件再执行，**禁止内联**
   - 写文件 → 禁止逐字符 join
   - 统计数字 → 带口径标签，禁止裸数字
