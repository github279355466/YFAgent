# knowledge/ — 知识资产

构建期输入（源）与派生产物的分离设计。**派生产物可从源机械重建，源不可重建**。

## 目录结构

| 路径 | 性质 | 入库 | 说明 |
|---|---|---|---|
| `typekey/` | 🟡 **派生产物** | ✅ | TypeKey 映射表（106 对象 / 595 服务名） |
| `typekey-mapping/` | 🟡 **派生产物** | ✅ | 字段对照表（106 个 md / 12,893 字段） |
| `official/` | 🔵 **源** | 部分 | 官方文档原件（`_raw/` 大文件不入库） |
| `enums/` | 🔵 源 | ✅ | 枚举字典（待收集） |
| `glossary/` | 🔵 源 | ✅ | 术语表（待收集） |
| `faq/` | 🔵 源 | ✅ | 常见问题与话术（待收集） |

## 🔴 禁止手工编辑派生产物

`typekey/` 与 `typekey-mapping/` 是脚本产物，手工修改会被以下命令覆盖，且 `--check` 会检出不一致：

```bash
npm run gen:all      # 重新生成
npm run check:all    # 校验（CI 门禁）
```

## 每份对照表包含什么

以 `typekey-mapping/sales.order.md` 为例：

- **业务主键**（从 `read.get` 的 `datakeys` 抽取，含复合主键标注）
- **单头字段**（`create` ∪ `update` 入参并集，标注必填/可选/可写三态）
- **单身字段**（按 `*_data` 节点分组，标注 `node_name` 查询要求）
- **通则字段**（管理字段 7 个 + 自定义字段 24 个，附易助对照警示）
- **写操作约束**（官方通则原文摘录）
- **⚠️ 文档异常**（官方文档的复制粘贴错误，非抽取缺陷）

## 易飞 vs 易助的关键差异（勿套用易助经验）

| 项 | 易飞 | 易助 |
|---|---|---|
| 字段编号体系 | ❌ 无 | ✅ 有（`XGA001` 等） |
| 自定义字段 | `udf01~12` / `udf51~62` | `udf_text1~16` / `udf_no1~16` |
| 管理字段 | 7 个（含 `company`/`flag`） | 4 个 |
| `conditions` 结构 | 对象 + `fields[].group` | 数组 + `groups` |

详见 `../docs/plans/yf-vs-yizhu-openapi-diff.md`。
